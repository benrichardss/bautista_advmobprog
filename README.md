# bautista_advmobprog

Lab Activity 2: The model, service, and screen work together to retrieve, organize, and display data from the DummyJSON API. The ProductService is responsible for communicating with the API endpoint and sending an HTTP GET request to retrieve the product data. Once the response is received, the JSON data is converted into Product objects using the Product.fromJson() factory constructor in the Product Model. The model defines the structure of the product data, including details such as the title, price, description, images, dimensions, reviews, warranty, shipping information, and other fields provided by the API. After the service returns the list of Product objects, the ProductScreen uses a FutureBuilder to handle the asynchronous request and render the products in a grid. When a product card is clicked, the selected Product object is passed to the ProductDetailsScreen, which uses the model's data to display the complete product information without needing to make another API request.

The new design pattern introduced in this activity follows a separation of concerns, where different parts of the application are responsible for specific tasks. The Model handles the structure and conversion of API data, the Service handles communication with the external API, and the Screens handle the presentation and interaction with the user. This creates a structure similar to the Model-Service-View (MSV) pattern. Separating these responsibilities makes the application easier to understand, maintain, and modify. For example, changes to the API connection can be made in ProductService without changing the UI, while changes to how products are displayed can be made in the screens without modifying the API logic. The activity therefore demonstrates how organizing an application into separate layers can make Flutter applications more scalable and easier to manage.
