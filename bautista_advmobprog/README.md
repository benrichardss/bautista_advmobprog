# bautista_advmobprog

Lab Activity 3: The cart feature follows a simple Model–Service–Screen design pattern, where each part has a specific responsibility. The Cart and CartProduct models represent the data received from the DummyJSON API, while CartService handles API requests such as retrieving a user's cart through getCartByUserId(). The CartScreen then uses the returned cart data to dynamically display the products, quantities, prices, discounts, and totals. When a user taps a product in the cart, the product ID stored in CartProduct is passed to ProductService.getProductById(), which retrieves the complete product information and sends it to the same ProductDetailsScreen used elsewhere in the application. This updated design improves code reusability because a separate detail screen is not needed for cart products. The Cart endpoint can also use a getById method, such as GET /carts/{cartId}, which retrieves a specific cart using its cart ID instead of the user's ID. Therefore, getCartByUserId() is useful for initially finding a user's cart, while getCartById() is useful when the application already knows the specific cart ID. Overall, separating the models, services, and screens keeps the application organized, reusable, and easier to maintain.
